0. Automated (PowerShell)

Preferred: run scripts/Register-M365BackupApp.ps1 as Global Admin in the customer tenant. It creates the app, grants Graph application permissions (admin consent), and prints Tenant ID, Client ID, and client secret.

.\Register-M365BackupApp.ps1 -RedirectUri "{{.RedirectURI}}"

Existing app (add missing permissions, keep secret): .\Register-M365BackupApp.ps1 -AppId "<client-id>"

Windows Server / RDP / “window handle must be configured”: add -UseDeviceCode.

1. App registration in Entra Admin Center

  1. Open entra.microsoft.com (or Azure Portal → App registrations) and sign in as Global Administrator or Application Administrator in the customer tenant.
  2. Go to Identity → Applications → App registrations → New registration.
  3. Name e.g. M365 Backup. Under Supported account types: Accounts in this organizational directory only (Single tenant). Leave Redirect URI empty for now → Register.
  4. On the overview note:
    • Application (client) ID → field below
    • Directory (tenant) ID → field Azure Tenant ID

2. Create a client secret

  1. Certificates & secrets → Client secrets → New client secret.
  2. Description e.g. m365backup, validity preferably 12–24 months.
  3. Copy the Value immediately (shown only once) → field Client secret. Expiry → field Secret expires.

Token renewal: Access tokens (OAuth) are renewed automatically via client credentials. The client secret itself is currently not rotated automatically — the app warns before expiry (30/7 days). Create a new secret before expiry and update it here.

3. API permissions (Application permissions)

Under API permissions → Add a permission → Microsoft Graph → Application permissions (not Delegated):

PermissionUsed forRequired
User.Read.AllUser list for Mail/OneDrive{{.L.T "common.yes"}}
Mail.ReadExchange user + shared mailboxes (EML){{.L.T "common.yes"}}
Files.Read.AllOneDrive + SharePoint files{{.L.T "common.yes"}}
Sites.Read.AllSharePoint sites{{.L.T "common.yes"}}
Team.ReadBasic.AllList teams (names/IDs){{.L.T "common.yes"}}
Channel.ReadBasic.AllList channels in a team{{.L.T "common.yes"}}
ChannelMessage.Read.AllTeams channel messages{{.L.T "common.yes"}}
Chat.Read.AllTeams 1:1 / group chats{{.L.T "common.yes"}}
Application.Read.AllCheck secret expiry{{.L.T "common.recommended"}}
Mail.ReadWriteMail restore (optional){{.L.T "common.optional"}}
Files.ReadWrite.AllFile restore via Graph{{.L.T "common.optional"}}
Calendars.Read / Contacts.ReadCalendar/contacts (later){{.L.T "common.optional"}}

After adding: click Grant admin consent for <Tenant> in the portal or use the “Admin consent” button on the tenant page (safe to re-run on an active tenant — no new backup is started).

4. Redirect URI for admin consent

  1. Authentication → Add a platform → Web.
  2. Enter the redirect URI (exact, including https): {{.RedirectURI}}
  3. Save. No further redirects needed.

5. Enter values here

  1. After creating: open the tenant → Admin consent → customer confirms the permissions.
  2. Status becomes active; first backup jobs start automatically.

Secrets are encrypted with MASTER_KEY in the database — never commit plaintext to git.

0. Automatisch (PowerShell)

Empfohlen: scripts/Register-M365BackupApp.ps1 als Global Admin im Kunden-Tenant ausführen. Legt die App an, erteilt Graph Application Permissions (Admin Consent) und gibt Tenant ID, Client ID und Client Secret aus.

.\Register-M365BackupApp.ps1 -RedirectUri "{{.RedirectURI}}"

Bestehende App (fehlende Permissions nachziehen, Secret behalten): .\Register-M365BackupApp.ps1 -AppId "<client-id>"

Windows Server / RDP / „window handle must be configured“: -UseDeviceCode anhängen.

1. App-Registrierung im Entra Admin Center

  1. Öffne entra.microsoft.com (oder Azure Portal → App registrations) und melde dich als Global Administrator oder Application Administrator im Kunden-Tenant an.
  2. Gehe zu Identity → Applications → App registrations → New registration.
  3. Name z.B. M365 Backup. Unter Supported account types: Accounts in this organizational directory only (Single tenant). Redirect URI vorerst leer lassen → Register.
  4. Auf der Übersicht notieren:
    • Application (client) ID → Feld unten
    • Directory (tenant) ID → Feld Azure Tenant ID

2. Client Secret erzeugen

  1. Certificates & secrets → Client secrets → New client secret.
  2. Beschreibung z.B. m365backup, Gültigkeit möglichst 12–24 Monate.
  3. Value sofort kopieren (nur einmal sichtbar) → Feld Client secret. Ablaufdatum → Feld Secret expires.

Token-Renewal: Access-Tokens (OAuth) erneuert die App automatisch über Client Credentials. Das Client Secret selbst wird aktuell nicht automatisch rotiert — die App warnt bei Ablauf (30/7 Tage). Vor Ablauf manuell ein neues Secret anlegen und hier aktualisieren.

4. Redirect URI für Admin Consent

  1. Authentication → Add a platform → Web.
  2. Redirect URI eintragen (exakt, inkl. https): {{.RedirectURI}}
  3. Speichern. Keine weiteren Redirects nötig.

5. Werte hier eintragen

  1. Nach dem Anlegen: Tenant öffnen → Admin consent → Kunde bestätigt die Permissions.
  2. Status wird active, erste Backup-Jobs starten automatisch.

Secrets werden mit MASTER_KEY verschlüsselt in der Datenbank gespeichert — nie im Klartext ins Git.
